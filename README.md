| Блок | Проверки |
| --- | --- |
| Регистрация | Новый уникальный email; повторная регистрация занятого email |

## Запуск

Нужен Python 3.10+ и доступ к учебному стенду. Команды для PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest
```

По умолчанию используется API `https://qa-desk.education-services.ru/api`.
Другой адрес задаётся переменной окружения `API_URL`, включая часть `/api`.
Проверка TLS-сертификата включена. Тайм-аут подключения — 5 секунд, чтения — 30 секунд.

## Отчёт

В [allure-report/index.html](allure-report/index.html) находится автономный Allure-отчёт.
После скачивания репозитория этот файл можно открыть в браузере.
На GitHub HTML отображается как исходный код.

Отчёт содержит шаги API, тела запросов, коды и тела ответов, а также подготовку и очистку данных.
Пароли и токены скрыты во вложениях.

Для обновления отчёта после запуска тестов нужен Node.js:

```powershell
npx --yes allure@3.33.0 generate allure-results --output allure-report --clean
```

Папка `allure-results` очищается перед каждым прогоном и не хранится в Git.

## Исследование API

Регистрация, создание, изменение и удаление объявления проверены через интерфейс сервиса.
Методы, пути и способ сборки запросов определены по вызовам публичного клиента приложения;
коды и тела ответов подтверждены отдельными запросами через `requests`.
Контракт и примеры находятся в [docs/api.md](docs/api.md).

## Данные и независимость

Каждый тест получает отдельные данные и собственную HTTP-сессию.
Email генерируется через UUID в отдельном модуле. Для проверки повторной регистрации
сначала создаётся новый пользователь, затем повторно отправляется именно его email.
Пароли также генерируются; готовые аккаунты и постоянные токены не нужны.

Фикстуры создают пользователей и объявления для предусловий.
После каждого теста с объявлениями очищаются записи только его нового пользователя.
Очистка проверяет код и тело ответа; после теста удаления повторное удаление не вызывается.
Тестовые пользователи остаются на стенде: запрос их удаления от обычного аккаунта возвращает 401.

## Структура

- `test/` — пять модулей и пять классов по функциональным блокам задания.
- `api/` — HTTP-клиент и методы регистрации, входа и работы с объявлениями.
- `helpers/generators.py` — генерация email и пароля.
- `helpers/models.py` — модели тестовых учётных данных и пользователя.
- `helpers/reporting.py` — вложения Allure с маскированием секретов.
- `data.py` — исходные данные, варианты параметризации и ожидаемые сообщения.
- `conftest.py` — предусловия и очистка данных.
- `docs/api.md` — исследованный контракт API.
