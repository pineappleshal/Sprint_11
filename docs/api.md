# Исследованный контракт API

Дата проверки: 25.11.2026. Базовый адрес: `https://qa-desk.education-services.ru/api`.

В интерфейсе выполнены регистрация, создание объявления без фотографий, изменение названия и удаление.
Пути запросов, поля и типы содержимого установлены по публичному клиенту
[main.672da7a6.js](https://qa-desk.education-services.ru/static/js/main.672da7a6.js).
Ответы ниже подтверждены запросами к учебному стенду. Идентификаторы в примерах условные;
в тестах они всегда берутся из ответа сервера.

## Ручки

| Метод и путь | Содержимое запроса | Успешный ответ |
| --- | --- | --- |
| `POST /signup` | JSON: `email`, `password`, `submitPassword` | 201: `user`, `access_token.access_token` |
| `POST /signin` | JSON: `email`, `password` | 201: `user`, `token.access_token` |
| `POST /create-listing` | multipart/form-data: поля объявления | 201: созданное объявление |
| `PATCH /update-offer/{id}` | multipart/form-data: поля объявления и `img1`, `img2`, `img3` | 200: изменённое объявление |
| `GET /profile/listings/1` | Без тела | 200: `offers`, `totalPages` |
| `DELETE /listings/{id}` | Без тела | 200: сообщение об удалении |

Запросы к объявлениям используют заголовок `Authorization: Bearer <token>`.
У регистрации и входа различается вложенность токена; в обоих случаях внутреннее поле называется `access_token`.
Работоспособность каждого вида токена проверяется запросом к списку объявлений нового пользователя.

## Регистрация и вход

Регистрация:

```json
{
  "email": "vk_desk_<uuid>@example.com",
  "password": "<сгенерированный пароль>",
  "submitPassword": "<тот же пароль>"
}
```

Ответ 201:

```json
{
  "user": {"id": 123, "name": "User", "email": "vk_desk_<uuid>@example.com"},
  "access_token": {"access_token": "<token>"}
}
```

Повторная регистрация возвращает **400**:

```json
{"statusCode": 400, "message": "Почта уже используется"}
```

Вход отправляет `email` и `password`. Ответ **201** содержит того же пользователя:

```json
{
  "user": {"id": 123, "name": "User", "email": "vk_desk_<uuid>@example.com", "avatar": null, "admin": false},
  "token": {"access_token": "<token>"}
}
```

## Объявления

Поля multipart-формы:

| Поле | Пример | Тип в форме / ответе |
| --- | --- | --- |
| `name` | Учебное объявление | Строка / строка |
| `category` | Авто | Строка / строка |
| `condition` | Новый | Строка / строка |
| `city` | Москва | Строка / строка |
| `description` | Описание тестового товара | Строка / строка |
| `price` | 1750 | Строка / число |

В клиенте доступны категории «Авто», «Книги», «Садоводство», «Хобби», «Технологии»;
состояния «Новый» и «Б/У».
Фотографии необязательны. При редактировании объявления без фотографий клиент передаёт
`img1`, `img2`, `img3` со строкой `null`; тестовый клиент воспроизводит этот формат.

Для multipart используется `requests` с `files={имя: (None, значение)}`.
Библиотека формирует boundary и соответствующий Content-Type автоматически.

Ответ создания или изменения содержит все шесть полей, `id`, `owner`, временные метки
`createdAt`, `updatedAt`, а также `img1`, `img2`, `img3` и `isFavorite`.
В тестах сверяются все редактируемые поля и владелец, затем сохранённая запись
повторно запрашивается через список объявлений пользователя.

Попытка изменения объявления другим пользователем возвращает **401**:

```json
{
  "message": "Оффер не найден или у вас нет прав на его редактирование",
  "error": "Unauthorized",
  "statusCode": 401
}
```

Проверяется не только отказ, но и полное совпадение исходной записи после него.

Успешное удаление возвращает **200**:

```json
{"message": "Объявление удалено успешно"}
```

После удаления единственного объявления список владельца:

```json
{"offers": [], "totalPages": 0}
```

## Очистка

Каждый тест с объявлениями создаёт своего владельца и одну запись.
В финализаторе фикстуры читается его список; оставшаяся запись удаляется,
код 200 и сообщение об удалении проверяются. Уже удалённая запись в список не попадает.

Удаление пользователей (`POST /delete-user/{id}`) недоступно обычному тестовому аккаунту:
стенд возвращает 401 с сообщением «У вас нет прав». Поэтому эта ручка не используется в финализаторах.
